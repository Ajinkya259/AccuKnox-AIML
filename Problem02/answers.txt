2. KEY COMPONENTS OF AN LLM CHATBOT

1.  UI: the place where users talk to the bot, could be a website, app, WhatsApp or even a call.
2.  LLM provider: the model that actually genrates replies, like OpenAI, Anthropic or Llama.
3.  System prompt: basic rules for the bot, how it should talk and what it shouldnt answer.
4.  Knowledge (RAG): pulls the relevent company docs and passes them to the model.
5.  Tools: so the bot can do things, like look up an order or raise a ticket.
6.  Context and memory: what the bot keeps from earlier chats and about the user.
7.  Guardrails: to stop wrong, unsafe or off-topic answers.
8.  Rate limits and cost: keeping API calls and spend under control.
9.  Tracing/observability: logs each step so when somthing breaks we can see why.
10. Evaluation: regular testing to make sure answers don't get worse over time.


3. VECTOR DATABASES

What is it?
A vector database stores text as lists of numbers (vectors) and finds items that
are similar in meaning, not just exact word matches.

For example, "I forgot my password" and "How do I reset my login?" use different
words but mean the same thing. A vector database knows they are close.

How it works
1. Split documents into small chunks.
2. Convert each chunk into a vector using an embedding model.
3. Store the vectors along with details like date and category.
4. Convert the user's question into a vector.
5. Return the closest matches.

Common options
- FAISS    : fast search library, not a full database
- Pinecone : managed cloud service, nothing to set up
- Qdrant   : open source, can run on your own servers, strong filtering
- pgvector : adds vector search to PostgreSQL
- Chroma   : simple, good for small projects

My choice
Problem: a security team wants an assistant that finds past incidents similar to
a new alert. Results must be filtered by severity and date, and the data must stay
on the company's own servers.

I would choose Qdrant, because:
- Data stays in-house: it can run on the company's own servers.
- Filtering: it can search for "similar incidents, critical only, from the last 90 days".
- Keyword and meaning search: it also finds exact terms like CVE numbers and IP addresses.
- Fast and free to self-host.

From my work: I have used Pinecone in a voice support agent, and FAISS with keyword
search over 13.98 million Wikipedia passages.
